# 1小時超精簡版：一頁網頁實作課

預設路線：Lovable生成與調整 → GitHub保存自己的程式碼 → GitHub Pages自動發布成網址。

## 課前準備

- 課前完成Lovable與GitHub登入、信箱驗證、Lovable剩餘額度確認；新授權由本人操作。
- 每人一台電腦、可連網；準備純文字編輯器，顯示副檔名。先備份教材範本，平台等待時可繼續。
- 講師先走過整條路線；60分鐘不含帳號註冊、授權故障與長時間平台排隊。
- 目標是三段流程和一次改版；ChatGPT、Claude、進階作業與完整QA留到延伸教材。

## Lovable｜生成與調整（00–25 分鐘）

看見第一版、做一次修改，取得可獨立開啟的HTML。

1. **開啟已登入的 Lovable**：前往 https://lovable.dev/，在首頁的需求輸入區貼上下方「活動頁生成提示詞」，選擇開始建置的按鈕（常見為 Build／送出）。等待第一版；1～2分鐘是體驗目標，實際時間依平台而定。

![貼上「最快體驗版」提示詞，確認右下為 Build，再按黑色箭頭送出。](../assets/onehour/01-lovable-prompt-s1-1.svg)

![送出後進入專案；輸入框右下的方塊鈕表示 Lovable 仍在建置。](../assets/onehour/02-lovable-building-s1-1.svg)

2. **檢查第一版**：在預覽中找到活動名稱、日期、地點及行程。點一次地圖、勾一個清單項目，切換窄版預覽確認手機文字和按鈕。

![第一版完成：在右側預覽核對活動名稱、日期與地點。](../assets/onehour/03-lovable-first-preview-s1-2.svg)

![按上方裝置鈕切換成手機預覽，檢查文字與按鈕是否清楚。](../assets/onehour/06-lovable-mobile-preview-s1-2.svg)

3. **送出一次明確修改**：貼上「單次修改提示詞」，只改標題和手機按鈕。確認修改真的出現在預覽。

![在左下輸入框貼上「單次修改提示詞」後送出。](../assets/onehour/04-lovable-modify-prompt-s1-3.svg)

![修改後標題變成「週末森林小旅行」，左側列出這次改了哪兩項。](../assets/onehour/05-lovable-modified-preview-s1-3.svg)

4. **取得獨立靜態檔**：確認專案內確實有 public/workshop/index.html。若尚未建立，貼上「獨立HTML匯出提示詞」。原專案同步GitHub後可在該檔案頁點 Raw，或在Lovable的Code開啟檔案後選Copy file content，複製全部內容，用純文字編輯器另存 index.html（UTF-8，避免變成 index.html.txt）；若工具直接提供完整HTML，亦可照此存檔。不要只複製原框架的入口HTML。

![Lovable 回報還沒有 public/workshop/index.html 時，貼上「獨立HTML匯出提示詞」。](../assets/onehour/07-lovable-export-prompt-s1-4.svg)

![在 Code 開啟 public/workshop/index.html，用複製鈕或 Download 取得完整檔案。](../assets/onehour/13-lovable-export-file-s1-4.svg)

5. **雙擊驗收**：雙擊剛存的 index.html，在本機再次測試地圖、導覽及清單。離開Lovable仍可操作，才是本課可發布的靜態檔。

![存成 index.html 後雙擊，在本機瀏覽器仍能看到完整活動頁。](../assets/onehour/14-local-html-1440-s1-5.svg)

![同一份檔案的手機寬度：主要按鈕占滿寬度、文字清楚。](../assets/onehour/14-local-html-390-s1-5.svg)

### 超精簡活動提示詞（預設）

**最快體驗版**

請幫我做一頁「週末自然散步」活動網頁。示範日期是2026年12月12日上午9點到12點，地點是大安森林公園。放上活動介紹、時間地點和集合地圖，風格自然清爽，並標示這是虛構教學活動。

**資訊清楚版**

請做一頁「週末自然散步」活動介紹，讓朋友一眼看懂什麼時候、在哪裡、要帶什麼。示範活動是2026年12月12日上午9點到12點，在大安森林公園。請加上簡單行程、地圖與常見問題，並標示沒有真實招募。

**帶清單版**

幫我製作一頁虛構的「週末自然散步」活動網頁：2026年12月12日上午9點到12點，大安森林公園。除了時間、地圖和行程，再做一份可以勾選的水壺、鞋子、防曬及雨具清單。畫面請用舒服的森林感。

**手機友善版**

請做一頁手機也好讀的「週末自然散步」活動網頁。示範日期2026年12月12日，上午9點到12點，地點大安森林公園。字要清楚，集合地圖按鈕要容易點，包含活動介紹、行程和準備事項，並標示為虛構教學示範。

### 活動頁生成提示詞

```text
請製作一個繁體中文（台灣用語）的一頁式活動網頁，主題為「週末自然散步」。這是虛構教學活動，請清楚標示「教學示範，沒有真實招募」。

活動資料：
- 示範日期：2026/12/12，09:00–12:00。
- 地點：臺北市大安森林公園；這是公開景點的示範，不代表真實集合安排。
- 對象：想在週末輕鬆散步的朋友。
- 行程：09:00集合暖身、09:30自然觀察、11:00休息分享、12:00結束。
- 準備清單：飲用水、好走的鞋子、帽子與防曬、雨具。
- FAQ：下雨怎麼辦、需要裝備嗎、這個頁面會收集個資嗎。
- 主要按鈕：「查看集合地圖」，連到 https://www.google.com/maps/search/?api=1&query=大安森林公園 ，另開分頁並加上 rel="noopener"。

版面與功能：
- 使用森林綠 #193f32、霧白 #f1f3ec、淺葉綠 #d9e9a4。
- 手機、平板、桌機依可用寬度重排，字體清楚、沒有橫向溢出。
- 有頁內導覽、活動資訊、行程、可勾選的準備清單與FAQ。
- 清單可勾選並顯示完成數量，使用此瀏覽器的本機儲存保留勾選；按鈕與連結都要能操作，保留鍵盤焦點。
- 不加入登入、資料庫、付款、報名表、平台內建AI、API或金鑰。

先產生可預覽第一版。完成後請另外建立一份 public/workshop/index.html：完整的獨立靜態網頁，CSS與JavaScript全部內嵌，不依賴框架、外部套件、伺服器或Lovable執行環境。讓我下載或從同步至GitHub的檔案中取得後，雙擊就能使用，再交給GitHub Pages發布。請不要把原專案的框架入口檔冒充獨立HTML。若尚未建立此檔，明確告訴我，並提供完整HTML原始碼。
```

## GitHub｜保存自己的程式碼（25–45 分鐘）

保存Lovable原專案，再將獨立HTML放到公開的教學發布儲存庫。

1. **連接並同步原專案**：在Lovable的聊天輸入區左下角按「＋」（Chat actions），選 Project → GitHub。使用既有帳號連線；若尚未連接，依介面選 Add connection／Add account，由學員本人完成登入與GitHub app授權。再於Accounts選 Connect，等待同步。此功能與GitHub API connector不同。

![輸入區左下角按「＋」，指向 Project。](../assets/onehour/35-lovable-chat-actions-s2-1.svg)

![在 Project 子選單選 GitHub。](../assets/onehour/21-lovable-project-github-menu-s2-1.svg)

![選自己的 GitHub 帳號按 Connect（講師畫面中的另一個帳號已遮蔽）。](../assets/onehour/22-lovable-connect-account-s2-1.svg)

2. **確認自己的程式碼已保存**：選 View on GitHub，看到原專案檔案及最新提交紀錄。Lovable新建的同步儲存庫預設私人；這份是原專案備份，不直接當Pages成品。找到 public/workshop/index.html，依上一段方式取得靜態檔；若不存在，回Lovable要求建立並等同步。

![Connected 與 In sync with GitHub：原專案已建立私人儲存庫並同步 main。](../assets/onehour/23-lovable-github-synced-s2-2.svg)

3. **建立專用發布儲存庫**：在GitHub右上角「＋」選 New repository，名稱填 event-page，選 Public，加入README後建立。此課使用GitHub Free，因此發布儲存庫使用公開。僅放虛構活動HTML，不放私人資料或金鑰。保留Lovable來源儲存庫為私人；本課兩個儲存庫的用途不同。

![New repository：名稱 event-page、Public、打開 Add README，再按 Create repository。](../assets/onehour/08-github-new-repository-s2-3.svg)

![建立完成的 event-page 儲存庫，目前只有 README。](../assets/onehour/09-github-repository-created-s2-3.svg)

4. **新增 docs/index.html**：在 event-page 儲存庫選 Add file → Create new file。檔名輸入 docs/index.html（斜線會建立資料夾），貼上已本機驗收的完整HTML。選 Commit changes，填入「新增活動靜態頁」，提交至預設分支（本課以main示範）。

![Add file → Create new file。](../assets/onehour/10-github-add-file-menu-s2-4.svg)

![檔名輸入 docs/index.html（打斜線會自動變成資料夾），貼上完整 HTML 後按 Commit changes。](../assets/onehour/11-github-docs-filename-s2-4.svg)

5. **確認檔案與分支**：回到Code，確認main分支的docs資料夾內有index.html且內容完整。如果原專案的分支叫其他名稱，不影響本課新建event-page的main；Pages必須選實際放有docs檔案的分支。

![提交後確認 main 分支的 docs/index.html 與提交訊息「新增活動靜態頁」。](../assets/onehour/16-github-saved-code-s2-5.svg)

![Commits 中留下可追溯的提交紀錄。](../assets/onehour/17-github-commit-history-s2-5.svg)

講師提問：為什麼同步原始專案後，還另外放一份HTML到發布儲存庫？

## GitHub Pages｜自動發布成網址（45–60 分鐘）

設定一次發布來源，再用一次Commit驗證網站自動更新。

1. **開啟 Pages 設定**：在event-page儲存庫選 Settings，在側邊選單的Code, planning, and automation區找到Pages；若看不到Settings，確認自己是儲存庫管理者。

![Settings → 左側 Pages；尚未設定時 Branch 顯示 None。](../assets/onehour/24-pages-settings-s3-1.svg)

2. **選擇發布來源**：在Build and deployment的Source選 Deploy from a branch。Branch選main，Folder選/docs，按Save。若設定早已儲存且沒有變更，Save灰色是正常狀態，不必重設。這條路線不必另選GitHub Actions範本，也不要同時套用教材中的選用Actions設定。

![Source 選 Deploy from a branch。](../assets/onehour/28-pages-source-menu-s3-2.svg)

![Branch 下拉選 main。](../assets/onehour/31-pages-branch-menu-s3-2.svg)

![資料夾下拉選 /docs。](../assets/onehour/29-pages-folder-menu-s3-2.svg)

![確認 main 與 /docs 後按 Save。](../assets/onehour/32-pages-before-save-s3-2.svg)

3. **等待並開啟正式網址**：到Actions查看Pages部署是否完成；回Settings → Pages找Visit site／網站網址。用該連結開啟，格式通常是 https://你的帳號.github.io/event-page/ 。等待時間不固定，不以此格式猜測部署已成功。

![部署完成後上方出現 Your site is live 與正式網址；設定沒變時 Save 灰色是正常狀態。](../assets/onehour/30-pages-saved-s3-3.svg)

![Actions 可看到 pages build and deployment 執行成功。](../assets/onehour/33-pages-actions-s3-3.svg)

![開啟正式網址，看到第一次發布的活動頁。](../assets/onehour/20-pages-live-s3-3.svg)

4. **驗收並改一個字**：正式頁面確認標題、地圖與清單。回Code → docs/index.html，選編輯，把活動副標加上「歡迎一起散步」，Commit changes至main。等待部署成功，再重新整理正式網址，看到新文字即證明自動更新。

![在 docs/index.html 按編輯，於副標後加上「歡迎一起散步。」再 Commit changes。](../assets/onehour/34-github-edit-file-s3-4.svg)

![提交紀錄顯示只改了副標這一行。](../assets/onehour/25-github-update-commit-s3-4.svg)

![自動重新部署後，正式網址出現新增的副標。](../assets/onehour/26-pages-updated-s3-4.svg)

5. **交出兩個網址**：交event-page儲存庫網址與Pages正式網址，附一張手機畫面和一句修改紀錄。若尚未發布成功，註明待補；404時先查部署狀態、main/docs和index.html大小寫，不要反覆建立新專案。

![正式網址的手機寬度驗收；交件時另附儲存庫網址。](../assets/onehour/27-pages-mobile-s3-5.svg)
