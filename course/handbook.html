AI 小白的一頁式網頁實作課：學員逐步手冊

先用 Lovable 產生並修改網頁，再同步 GitHub、匯出靜態頁、設定 Pages 自動發布。最後依序補充 ChatGPT、Claude 製作與修改，兩條路線都先取得獨立 HTML，再由自己提交。

本教材查閱日期：2026-11-05。1～2 分鐘為開場體驗目標，並非平台保證。免費功能與限制以當日帳號畫面為準。

課前準備

  • 課前完成 Lovable 免費帳號登入，開啟首頁輸入區，確認剩餘建置額度。課堂以 1～2 分鐘看到第一版為體驗目標，實際時間依網路、平台及需求複雜度。
  • 註冊 GitHub 免費帳號、驗證信箱，確認可登入與通過雙重驗證。ChatGPT 免費帳號留作後半段補充，不要求 GitHub 連接。
  • 每人一台 Windows／Mac 電腦、充電器、Chrome／Edge、可收信的信箱與穩定 Wi-Fi。平板與手機用來驗收，不取代電腦實作。
  • 建立 ai-web-class 資料夾並顯示副檔名，準備記事本或純文字模式的文字編輯。課堂無須安裝 Node.js、Git 或付費外掛。
  • 講師事先以測試帳號完整走過 Lovable 生成、GitHub 授權、靜態匯出、Pages 發布。準備可用預覽、離線 sample/index.html 與 starter.html，並測試教室網路。
  • 示範只用虛構活動與公共地點。不要把真實聯絡資訊、名單、金鑰或私人照片放進會公開的專案。
  • 選用：先登入 claude.ai，於 Settings／Capabilities 檢查 Create and edit files（或 Cloud code execution and file creation）。本課採免費可用的 Artifacts／HTML 路線，不要求 Claude Code 或 GitHub 連接。

免費工具與 GitHub 能力

工具判定限制與依據課堂用法
Lovable Free可以github.com 整合適用 Free，可建立儲存庫並雙向同步。課堂主要製作與同步工具。
ChatGPT Free依帳號及介面官方沒有保證所有 Free 帳號都有 GitHub app；即使可連接也只讀取、搜尋與分析。用提示詞產出／修改檔案，再手動提交 GitHub。
一般 ChatGPT GitHub app不支援回寫不能自動 push、建立程式修改或 PR，不能等同 Lovable 同步。不作為本課發布步驟的前提。
GitHub Free＋Pages可以使用 public repository 發布靜態檔案。main /docs 收到提交後自動發布。
Claude Free可產生／修改作品Artifacts 可用；需要相關檔案製作能力與剩餘額度，外部 app 與資料儲存另依方案。接在 ChatGPT 後，以獨立 HTML 匯出、手動提交 GitHub。

1. Lovable：先看見第一版

目標：用最短需求立即看到 AI 產生網頁。

  1. 開課前已登入 Lovable。開場先不講名詞，在首頁輸入框貼 L1，選 Build 並送出，開始計時。
  2. 只做「週末自然散步」虛構活動，先不要登入、資料庫、付款、內建 AI 或 API。主要行動是查看集合地圖。
  3. 以 1～2 分鐘看到可觀察的第一版為目標，不保證完成時間。等待期間請學員找出活動名稱、日期、行程與地圖按鈕。
  4. 預覽出現後，立刻點一個導覽、開地圖、勾一個準備項目，感受生成的成果可以操作。此時是編輯預覽，還沒有 GitHub Pages 網址。
  5. 先記錄目前畫面與一個想改的地方，讓後續概念都對應到自己的作品。

完成檢查：能看見自己的第一版，並實際操作一個功能。

卡關備案：超過 2 分鐘仍在生成時，講師先展示預備好的成果；學員保留原任務等待，不重複送出消耗額度。

依據：Credits and usage、Quick start。

講師提問：現在看到漂亮的預覽，代表網站已經公開上線了嗎？

查看參考解答參考解答：還沒有。現在是 Lovable 的編輯預覽，稍後要把檔案同步到 GitHub，再由 Pages 發布，並用另一台裝置驗證。

2. 從成果整理需求

目標：先觀察結果，再把模糊想法改成可檢查的需求。

  1. 打開自己剛生成的頁面，指出文字內容、視覺樣式、點按互動各一項，再對照參考生活營手冊的資訊架構。
  2. 填工作單：讀者、主要行動、活動名稱、示範日期與地點、必要區塊、風格與驗收條件。
  3. 共同資料為「週末自然散步」，示範日期 2026/12/12 09:00–12:00，地點大安森林公園。內容是虛構練習，不是真實招募。
  4. 第一版只保留總覽、行程、準備清單、地圖與 FAQ。把「好看」改成例如「字大好讀、手機單欄、按鈕名稱明確」。

完成檢查：說得出目標讀者、主要行動與五個必要區塊。

卡關備案：想不出主題時使用共同示範，不把時間花在重新發想。

依據：範例：2026 生活營手冊。

講師提問：「幫我做得好看一點」可以換成哪些具體條件？

查看參考解答參考解答：例如內文至少 18px、390px 手機不橫向捲動、地圖按鈕標示動作、日期一眼找得到，這些都能實際檢查。

3. 在 Lovable 修改內容與排版

目標：完成內容與版面修改，再確認既有功能仍可用。

  1. 使用 L2 提出一組內容修改，例如活動名稱或三段行程。提供原文與新文，要求保留地圖、導覽和清單。
  2. 使用 L3 提出一組樣式修改，例如深綠主色、內文至少 18px、手機單欄、平板依內容重排。每次只處理一組相關問題。
  3. 若介面有 Visual edits／元素選取工具，可先選取標題或按鈕再修改。若功能受方案限制，改用文字提示詞即可。
  4. 用預覽的裝置模式或 Chrome／Edge 的裝置工具列測 1440、768、390px。不要留下空側欄，也不能把固定雙欄硬塞進手機。
  5. 每次修改後重點導覽、地圖與清單。截圖記錄修改前後差異，不只看顏色有沒有改。

完成檢查：完成一項內容修改、一項樣式修改，三種寬度可讀。

卡關備案：額度不足時停止反覆生成，改做既有頁面驗收，並以靜態範本完成後續流程。

依據：Credits and usage、Quick start。

講師提問：改完顏色後，為什麼還要再點一次地圖和清單？

查看參考解答參考解答：AI 可能同時調整到結構或程式。重測原本功能，才能確認新的外觀沒有弄壞既有操作。

4. 確認功能與平台限制

目標：分清楚目前頁面、版本、服務額度與發布狀態。

  1. 依工作單測導覽跳區、地圖位置、清單勾選與 Tab 焦點。指出至少一個待修問題，以 L4 回報重現步驟。
  2. 在 Lovable 記錄可用版本或截圖，保留目前需求。免費建置額度在查閱日為每日 5、每月最多 30，不等於 5 次指令。
  3. 清單只在目前頁面勾選，重新整理可重設。沒有表單後端就不能宣稱完成報名收件。
  4. 目前只用前端靜態資訊，避免讓發布綁定登入、資料庫、伺服器函式或金鑰。即使沒啟用後端，專案框架仍可能含伺服器程式。

完成檢查：能指出目前是預覽，知道額度與資料儲存限制。

卡關備案：卡關 5 分鐘先保留可用版，勿要求學員付費。

依據：Credits and usage、Connecting GitHub to ChatGPT、Deployment, hosting, and ownership options。

講師提問：免費建置額度有 5 點，就一定能送 5 次修改嗎？

查看參考解答參考解答：不一定。額度是用量單位，單次工作可能消耗不同點數，還受每月上限影響，應查看剩餘量。

5. 將程式碼同步到 GitHub

目標：在自己的 GitHub 帳號取得完整專案。

  1. 官方文件明示 Lovable 的 github.com 整合適用所有方案，包含 Free。學員使用自己的 GitHub 帳號，不共用密碼。
  2. 在 Lovable 開 Project settings／Git／GitHub／Add connection（有些介面顯示 Add account），選標準 github.com。
  3. 到 GitHub 授權視窗選自己的帳號，閱讀 Lovable GitHub app 的存取範圍。能選指定儲存庫就限縮到課堂用途；若尚未建庫，依授權流程建立後再檢查範圍。
  4. 完成 Install & Authorize，回 Lovable 在 Accounts 對自己的帳號按 Connect。平台會建立新儲存庫，預設 private。不要先建立同名空庫再要求匯入。
  5. 按 View on GitHub，確認檔案與最新 Commit，並查看 Lovable Sync status。通常使用 main，若分支名稱不同，後續都以實際同步分支為準。
  6. 同步是保存檔案，還不等於 Pages 已發布。先保留連接，後續靜態匯出仍要經這個連接同步。

完成檢查：自己的 GitHub 儲存庫看得到完整程式碼與最新提交。

卡關備案：授權視窗被擋時允許該站彈出視窗再重試。組織權限受限時改用個人教學帳號，仍保留限制紀錄。

依據：Sync your Lovable project with GitHub。

講師提問：程式碼同步到 GitHub，就已經完成對外發布了嗎？

查看參考解答參考解答：還沒有。同步只讓 GitHub 取得程式碼，還要準備可發布的靜態檔、設定 Pages，並確認部署成功。

6. 匯出能離線開啟的靜態網頁

目標：把完成的視覺與內容整理成不依賴 Lovable 執行的檔案。

  1. 先辨認專案檔案。官方說明新 Lovable 專案採用 TanStack Start，原始專案可能需要伺服器；GitHub Pages 只提供靜態檔，不能直接執行它。
  2. 在 Lovable 貼 L5，要求依目前完成的內容、排版和互動，新增 docs/index.html 獨立靜態頁，CSS／JavaScript 內嵌，圖片若有則一併放 docs/assets 並用相對路徑。保留原始預覽專案。
  3. 等同步完成，在 GitHub 的 docs 資料夾找到 index.html。若已有 docs 文件，先備份並確認用途；改用新的教學儲存庫，不覆蓋原有文件。
  4. 從 GitHub Code／Download ZIP 下載並解壓縮，雙擊 docs/index.html。免費路線透過 GitHub 取檔，不要求 Lovable 付費的 Download codebase 功能。
  5. 對照 Lovable 最終預覽，確認文字、顏色、間距、手機排版及功能。這是 AI 重新整理的靜態版本，必須實測，不能保證逐像素相同。
  6. 如果 L5 未產出可用檔案，使用教材的靜態匯出範本或將內容交給 ChatGPT 產生 HTML，再上傳 GitHub 的 docs/index.html，並完成同樣驗收。

完成檢查：下載後的 docs/index.html 能獨立開啟，且內容和必要功能一致。

卡關備案：額度不足時用已準備的 portable/docs/index.html，替換活動內容後完成部署。

依據：Sync your Lovable project with GitHub、Deployment, hosting, and ownership options、Downloading source code archives。

講師提問：為什麼不能把 Lovable 的原始專案直接指定成 Pages 首頁？

查看參考解答參考解答：新專案可能需要伺服器，Pages 只會送出靜態檔。先匯出完整 HTML、CSS 與瀏覽器互動，才符合本課的主機能力。

7. GitHub Pages 自動發布

目標：設定一次發布來源，後續提交靜態頁就自動更新。

  1. 先確認整份儲存庫及提交歷史都只有可公開的練習資料。Lovable 新建儲存庫預設 private，GitHub Free 的 Pages 需要 public repository。
  2. 若確定是可公開的教學專案，到 GitHub Settings／General／Danger Zone／Change repository visibility，改為 Public 並完成介面確認。若不能公開原專案，就建立新的 public 教學庫，只上傳靜態 docs 檔案。
  3. 在儲存庫開 Settings／Pages，Source 選 Deploy from a branch，Branch 選同步的 main，資料夾選 /docs，再 Save。這裡不是 /(root)，也不是把整個 src 放上去。
  4. 到 Actions 查看 Pages 的部署紀錄，成功後回 Pages 按 Visit site，複製實際網址。一般專案格式為 https://你的帳號.github.io/儲存庫名稱/，網址不加 /docs。
  5. 請同學用另一台裝置或無痕視窗開正式網址。發布可能需數分鐘，官方提醒有時可到 10 分鐘，未完成就註記待補。
  6. 以後 docs/index.html 所在的發布分支有新提交，Pages 會自動更新。若只改 Lovable 原始預覽而沒更新靜態匯出，正式網站不會跟著變。

完成檢查：取得正式 Pages 網址，另一台裝置可以開啟。

卡關備案：404 時檢查 docs/index.html 大小寫、發布分支、/docs 來源與 Actions；等待期間先驗收本機版。

依據：Creating a GitHub Pages site、Configuring a publishing source、Setting repository visibility。

講師提問：網址要加上 /docs 才能看到頁面嗎？

查看參考解答參考解答：不用。/docs 是儲存庫內的發布資料夾，網站根目錄會對應它的內容，應以 Pages 的 Visit site 網址為準。

8. 離開 Lovable 更新作品

目標：直接修改 GitHub 檔案，驗證自動發布並了解雙向同步。

  1. 先從 GitHub 下載 ZIP 作為快照，再開 docs/index.html 按鉛筆編輯。只改一段活動文字，保留 HTML 標籤與連結。
  2. 填明確的 Commit message，例如「更新活動集合說明」，提交到發布分支。若介面要求 Pull request，建立後合併至發布分支。
  3. 記下提交時間與識別，等待 Actions 完成，重新打開正式網址檢查新文字。這次不回 Lovable 修改，也不用按 Lovable Publish。
  4. 仍連接 Lovable 時，GitHub 同步分支的改動可能同步回平台。不要讓兩邊同時編輯同一檔，避免互相覆蓋。
  5. 若要完全停止使用 Lovable，確認 GitHub 備份與 Pages 可用後，才在 Lovable 的 Git 連接選單 Disconnect project。斷開後檔案仍在 GitHub，但不再雙向同步。
  6. 後續可選擇以 docs/index.html 為唯一正式檔，或每次在 Lovable 改版後重新匯出 docs 並同步，再交給 Pages 自動發布。兩種維護方式要說清楚。

完成檢查：直接在 GitHub 更新一次，正式網址自動顯示新版。

卡關備案：改壞時先用已下載的可用快照還原 docs/index.html，重新提交並重測。

依據：Sync your Lovable project with GitHub、Configuring a publishing source、Downloading source code archives。

講師提問：直接在 GitHub 改 docs/index.html，還需要按 Lovable Publish 嗎？

查看參考解答參考解答：不需要。網站由 GitHub Pages 發布，提交到發布分支後會觸發更新。Lovable Publish 只更新 Lovable 的託管版本。

9. ChatGPT 補充製作與修改路線

目標：用免費對話產生檔案，手動提交到同一條發布流程。

  1. 先讀免費能力表。ChatGPT 免費可用文字提示詞產生與修改 HTML。GitHub app 的可用性依方案與介面，官方未保證所有 Free 帳號皆能連接。
  2. 若要檢查自己的連接，開 Settings／Plugins（舊介面可能是 Apps），找 GitHub。若未出現或顯示方案限制，就不要把連接當課堂前提。
  3. 即使能授權 GitHub，官方文件說 app 只供讀取、搜尋與分析，不能 push 程式碼或自動雙向同步。Codex 是另一路程式工具，不等於一般 ChatGPT 對話。
  4. 新頁面使用 C1，後續修改使用 C2 或 C3，貼目前最新完整 HTML 並要求只改一件事、回傳完整檔案。
  5. Windows 用記事本另存 index.html，類型選所有檔案、UTF-8；Mac 文字編輯先選製作純文字。確認沒有 .txt，雙擊檔案預覽。
  6. 在 GitHub 的 docs 資料夾選 Add file／Upload files，上傳同名 index.html 並提交。或用鉛筆貼上完整內容。這是手動提交，後面的 Pages 發布才是自動。

完成檢查：能說明 ChatGPT 產檔、手動提交、Pages 自動發布的分工。

卡關備案：看不到 GitHub app 不影響課程，直接貼 HTML 到對話並手動上傳。

依據：ChatGPT Free Tier FAQ、Adding a file to a repository、Connecting GitHub to ChatGPT。

講師提問：ChatGPT 看得到 GitHub，就能自動幫我把新網頁推上去嗎？

查看參考解答參考解答：不能這樣推論。一般 GitHub app 是唯讀，Free 可用性也不保證。此路線由自己提交 HTML，再讓 Pages 自動發布。

10. Claude 製作與修改路線

目標：用 Artifacts 產生並調整網頁，匯出可自行維護的 HTML。

  1. 在 ChatGPT 補充之後，開 claude.ai 並登入。免費方案可使用 Artifacts，先確認當日剩餘額度，不要求安裝 Claude Code 或連接 GitHub。
  2. 開 Settings／Capabilities，確認 Create and edit files 已開啟；舊介面可能寫 Cloud code execution and file creation。若受工作區限制，以實際權限為準，不擅自調整組織安全設定。
  3. 在新對話貼 CL1。可從 Output 選 Design，或要求建立可編輯的網頁作品。先用相同的虛構活動、明確區塊與裝置限制，不加入登入、資料庫或內建 AI。
  4. 成果出現後，測導覽、地圖與清單。使用 CL2 一次改一件事，貼最新完整 HTML 或清楚指定正在編輯的作品，要求保留原功能及頁尾授權。
  5. 使用 CL4 要求獨立 index.html。Design 作品可從 Export 選 standalone HTML；若匯出 ZIP，先解壓並確認入口和資源。若只取得程式碼，複製完整 HTML 用純文字編輯器存為 UTF-8。
  6. 關閉 Claude 的預覽視窗後，用本機瀏覽器開 HTML，測三種寬度與功能。若仍依賴平台、伺服器或額外套件，請依 CL4 再整理為靜態單檔。
  7. 將驗收後的檔案手動上傳到 GitHub 的 docs/index.html 並提交，等待 Pages 成功部署。Artifacts 預覽、分享或匯出不等於已提交 GitHub。

完成檢查：能匯出獨立 HTML，修改一段內容並提交 GitHub，說明 Pages 才負責發布。

新手常見問題與專有名詞

以下為依入門操作常見卡關情境編製的教學題庫，並非經統計排名的調查。涉及產品規則已查官方文件。

完全不會寫程式也可以嗎？

可以先學會說明需求、存檔、預覽與驗收。至少能辨認標題、連結和檔案位置，才有能力檢查 AI 的結果。

需要付費或信用卡嗎？

本課主線不要求付費或信用卡。AI 免費服務可能有額度與服務限制，講師提供離線 HTML 作備案。

Lovable、GitHub、Pages 和 ChatGPT 各做什麼？

Lovable 先產生與調整頁面，再同步程式碼到 GitHub。Pages 發布靜態匯出。ChatGPT 是補充產檔與修改路線，檔案由自己提交。

免費額度用完怎麼辦？

保存已生成作品與需求，用教材靜態範本繼續練習同步、提交與發布，不必為上課付費。生成的秒數與消耗額度均不保證。

為什麼同一句提示詞結果不一樣？

AI 會受模型、對話與生成差異影響。用明確內容與驗收條件縮小差異，不要求全班畫面完全一致。

AI 寫的一定正確嗎？

不一定。日期、地點、連結、互動與個資都需要人工檢查。看起來漂亮也可能有不能按的按鈕。

我只給 AI 網址，它會看到整頁嗎？

不保證。工具未必可開頁面或讀到互動內容。改提供有權分享的截圖、內容與需求，避免複製他人私人資料。

為什麼存出 index.html.txt？

編輯器用文字檔格式自動加上 .txt。顯示副檔名，另存時選所有檔案，確認最後只有 .html。

為什麼打開只看見程式碼？

先檢查副檔名，再確認檔案不是含反引號或富文字格式。用純文字儲存完整 HTML。

為什麼中文亂碼？

用 UTF-8 儲存並確認 head 中有 <meta charset="UTF-8">。避免以錯誤編碼反覆覆寫。

為什麼本機可以、上線卻壞掉？

常見原因是圖片沒上傳、大小寫不同、路徑錯誤或專案需要建置。單檔主線可減少這些問題。

為什麼 Pages 顯示 404？

檢查 docs/index.html 大小寫、發布分支、Pages 是否選 /docs，以及部署狀態。此路線的發布網址不加 /docs。

為什麼改好 GitHub 還是舊畫面？

先看部署是否成功，再重新整理或用無痕視窗測試。上傳與提交完成後仍需等待發布。

GitHub 儲存庫就是網站嗎？

儲存庫保存來源與版本，正式網站由 Pages 的 Visit site 開啟。docs 是來源資料夾，不是正式網址要追加的路徑。

私人儲存庫代表網站也私人嗎？

不能這樣推論。Pages 的網站可見性與方案另有規則，本課使用免費 public repository，內容視為公開。

Lovable 免費版可以同步 GitHub 嗎？

可以。官方文件明示 github.com 整合適用 Free、Pro 等所有方案，可雙向同步。新庫預設 private，Pages 免費路線另需公開可發布的儲存庫。

Lovable 新專案可以直接放 Pages 嗎？

不一定。官方目前新專案使用 TanStack Start，可能需要伺服器。課堂先另產生 docs/index.html 靜態匯出，不直接部署原始伺服器專案。

勾選清單會讓每個人同步嗎？

本課示範的勾選只影響目前頁面，重新整理會重設。跨裝置同步需要後端或其他服務。

能把報名表放進去嗎？

可連到自己建立的 Google 表單。先確認外部學員可填，再看回覆是否到達。畫出表單不代表資料已送出。

可以把 API key 寫在 HTML 嗎？

不要。瀏覽器可讀取前端程式碼。第一堂課不用金鑰，若未來需要，應另設安全的伺服器端處理。

脫離 Lovable 後還能修改嗎？

可以。GitHub 有檔案後可下載 ZIP 或直接編輯 docs/index.html，提交後讓 Pages 自動更新。斷開 Lovable 同步前先確認備份與網站可用。

想換圖片要怎麼做？

用有授權的圖片，上傳到相同資料夾，檔名大小寫保持一致，使用相對路徑並補 alt。避免直接引用別人的私人相簿。

需要買網域嗎？

本課不需要。GitHub Pages 提供 github.io 子網域。自訂網域通常另有費用，與網站內容是不同項目。

公開網址一定會被 Google 搜到嗎？

不一定。公開可開啟與搜尋引擎收錄不同，收錄需要時間，也不保證排名。

可以做付款、會員或真實客戶系統嗎？

這超出本課靜態頁範圍，涉及身分、資料儲存與服務規則。先保留展示功能，再另規劃合適的後端與主機。

ChatGPT 免費版能連 GitHub 並自動同步嗎？

GitHub 連接的可用性依帳號、方案和介面，官方未保證所有 Free 帳號都有。一般 GitHub app 即使可連也只讀、不 push；課堂採產檔後手動提交。

Google 表單為什麼同學不能填？

檢查是否已發布、是否限制組織或登入、填答者權限及是否停止收件。使用另一個帳號實際測一次。

關掉電腦後網站還在嗎？

本機 file:/// 需自己的檔案。已成功發布的 Pages 網站由服務提供，不依賴自己的電腦持續開機，仍受服務狀態與規則影響。

為什麼設定 main /docs，而不是 main /(root)？

本課把獨立靜態檔放在 docs，原專案可能含伺服器與 TSX。發布來源必須對準靜態首頁，不能把兩種架構混在一起。

改完 Lovable，Pages 會立即同步外觀嗎？

只有已匯出的靜態 docs 檔案同步到發布分支後，Pages 才會更新。若只改預覽原始碼，需重新匯出。直接在 GitHub 修改 docs 則可直接觸發發布。

一定能在 1～2 分鐘生成嗎？

這是開場體驗目標，不是服務保證。先用短提示詞做小範圍頁面，較慢時改看講師預備成果，避免反覆送出。

免費 Lovable 不能直接下載程式碼怎麼辦？

平台內 Download codebase 是付費功能。免費可先同步到 GitHub，再用 Code／Download ZIP 取得檔案快照。

後端伺服器端負責驗證、資料處理與其他邏輯的部分。
靜態網站把已準備好的檔案提供給瀏覽器，也可以有前端互動。
資料庫有組織地持久保存和查詢資料的系統。
API系統之間約定的資料或功能存取介面。
API key存取某項 API 的憑證，不能放在公開前端。
Git記錄檔案版本的工具。
GitHub保存程式碼及協作的服務平台。
Repository／Repo集中存放專案檔案和版本紀錄的儲存庫。
Commit一次有說明的版本紀錄。
Branch分開進行修改的版本分支，本課主線用 main。
Deploy／部署把可執行或可呈現的版本發布到主機供訪客使用。
GitHub PagesGitHub 提供的靜態網站發布服務。
Hosting／主機託管讓網站檔案持續可被訪客存取的服務。
Domain／網域易讀的網站名稱，例如 example.com。
HTTPS瀏覽器與網站之間使用加密連線的協定，不代表內容一定可信。
相對路徑依目前檔案位置尋找資源，例如 ./photo.jpg。
Cache／快取暫存舊資源以加速存取，有時讓你看到舊版畫面。
Build／建置把原始碼轉成可部署成品的過程，框架專案常需要。
Framework／框架提供既定結構的開發工具，例如 React 生態的專案架構。
Credit／額度平台計算用量的單位，不一定一個指令等於一點。
Local／本機目前自己電腦內的環境，與公開主機不同。
Debug／除錯找出問題、修正並確認其他功能仍可用。
靜態匯出把畫面整理成可由瀏覽器直接呈現的 HTML、CSS、JavaScript 與資源。
雙向同步兩端的指定分支交換修改，仍須處理版本與衝突，不代表網站已發布。
GitHub ActionsGitHub 執行自動工作流程的功能，也能負責檢查、建置與 Pages 部署。
發布來源Pages 要讀取的分支與資料夾，例如 main 的 /docs，或自訂 Actions 產物。
ArtifactsClaude 可建立、編輯與匯出的作品，預覽可用仍須另外驗收獨立檔。
Standalone HTML可獨立開啟的 HTML。本課將樣式與互動內嵌，減少平台依賴。
Export／匯出把作品轉成可下載的檔案格式，匯出後仍需儲存、驗收與提交。
Claude Code另一種面向程式專案的工具，本課一般 Claude／Artifacts 路線不要求使用。
